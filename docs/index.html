Identifying Content with Declining Search Performance

A machine-learning approach for identifying and prioritizing content that shows measurable signs of declining search performance.

Abstract

This study asks whether content showing measurable signs of declining search performance can be identified and ranked for review. We use search-performance data across February and March and define decline using a decrease in impressions of at least 20%. A Random Forest model is trained using a client-level split, with 40 clients used for training and 10 held out for testing. On the same evaluation split, the model achieved Precision@50 of 0.42 compared with 0.06 for the rule-based baseline. The resulting ranked queue is intended to support human review and prioritization rather than automatically deciding which content should be changed.

1. Introduction / Problem Statement

Search performance can change over time. Some content may continue to perform steadily while other content shows measurable deterioration. Reviewing every content item manually is difficult when the dataset is large.

The goal of this work is therefore to test whether machine learning can identify content with measurable signs of declining search performance and rank those items for review.

The output is designed as a prioritization tool. It does not claim that a model can determine the correct content strategy automatically.

2. Data

The analysis uses the FlyRank ML Internship dataset and compares search-performance information across February and March.

7,355,108 February rows
9,841,378 March rows
303,572 Final modeling rows
38,131 Declining rows

After preparation and filtering, the final modeling dataset contained 303,572 rows. The declining class contained 38,131 rows, representing 12.56% of the modeling dataset.

Public-safety handling

Client names, private queries, private URLs, and other client-specific information are not included in this public paper.

3. Methodology

Label definition

Declining content is defined as content where impressions decreased by at least 20% over the comparison period.

Features

Model inputs are based on available search-performance and content characteristics. Variables that directly reveal the target outcome were excluded to reduce target leakage.

Validation design

A client-level split was used so that clients in the test set were not also used to train the model. The split contained 40 training clients and 10 held-out test clients.

Model

The main model was a Random Forest classifier with 300 trees, class balancing, and a fixed random state for reproducibility.

Baseline

A rule-based baseline was evaluated on the same test split. This makes the model comparison more directly interpretable.

Evaluation metric

Precision@50 measures how many of the top 50 ranked items are actually members of the declining class. This metric matches the practical use case of creating a small review queue.

4. Results

Random Forest Precision@50: 0.42
Rule-based baseline Precision@50: 0.06
Approach Precision@50
Random Forest 0.42
Rule-based baseline 0.06

On the same held-out client split, the Random Forest produced a Precision@50 of 0.42, while the rule-based baseline produced 0.06. This result indicates that the model produced a more concentrated top-50 review queue under this evaluation setup.

Interpretation: This is an evaluation result for this dataset, label definition and validation design. It should not be interpreted as proof that the model will perform the same way on every future dataset.

5. Limitations & Honest Framing

  • The evaluation is based on the available internship dataset and comparison window.
  • Precision@50 measures ranking quality for a small review queue; it does not measure business impact directly.
  • A declining label identifies a measurable change in impressions, not the cause of that change.
  • Model performance can change when search behavior, content mix, or data distributions change.
  • The model should support human investigation rather than automatically changing content.
  • The public paper intentionally excludes private client information and private search queries.

6. Ranked Recommendations

The model output can be converted into a review queue using probability thresholds and reason codes.

1. Review first

Items with decline probability ≥ 0.80 should receive the earliest human review.

2. Prioritize review

Items with decline probability ≥ 0.60 and below 0.80 should be prioritized for investigation after the highest-confidence items.

3. Monitor

Items with decline probability ≥ 0.40 and below 0.60 can be monitored for additional evidence before taking action.

4. Protect / observe

Lower-probability items should generally remain outside the immediate intervention queue unless other evidence indicates a reason to review.

What should NOT be automated

The system should not automatically delete, rewrite, redirect, or publish changes to content. Those actions require human review and additional business and content context.
